Reference: API quick tables ​

One page of lookups: a class, one sentence, its key methods. For the semantics (where every injection point is, when a hook does not interfere), go to the files listed under Where to read the real implementations.

Coordinates and modules ​

Module / mod idCoordinateContents
fabric-api (aggregate)cn.enaium.fabricpvz:fabric-api:1.2.2No code; depending on this coordinate brings the five modules, and the aggregate jar carries them inside itself (jar-in-jar), so an installation has one file
api-basevia the aggregatePvzFabricApi, ModQuery, the event bus (api.event)
api-eventsvia the aggregateLawnEvents (gameplay), GameLifecycleEvents (lifecycle) and the two bridges
api-plantvia the aggregatePlantType, PlantRegistry, PlantOverrides, ProjectileOverrides, BoardOverrides, CustomPlantEvents, PlantRules, PlantHooks
api-resourcevia the aggregateModImages, ModImageSlot, GameArt, ModReanims, ResourceOverrides, ResourceDiagnostics
api-zombievia the aggregateZombieType, ZombieRegistry, ZombieOverrides, CustomZombieEvents, ZombieHooks

The API is an optional dependency: when the sources use it, the mod declares cn.enaium.fabricpvz:fabric-api:1.2.2 itself (compileOnly / testCompileOnly for compilation, testImplementation / pvzRunClasspath with isTransitive = false for runtime), and lists the module ids (or "fabric-api") in its fabric.mod.json's depends. A mod that does not use the API declares no coordinate at all. The toolchain neither supplies the API nor picks its version.
